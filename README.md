# Аналитик банковских выписок

Учебный проект: агент, который отвечает на вопросы о личных расходах по банковской выписке.
Пользователь загружает CSV-выписку, а агент с помощью инструментов ищет операции, считает
расходы по категориям и месяцам и находит подписки и регулярные платежи.

Используем только синтетические выписки. Спецификация агента — пользователь, инструменты,
опасные действия, сценарии отказа — в [docs/SPECIFICATION.md](docs/SPECIFICATION.md).

## Что умеет (ДЗ1)

- **Загрузка выписки** командой `/load` или флагом `--statement`. Каждая строка проверяется;
  при ошибках файл не загружается, а сообщение указывает номера строк.
- **Три инструмента** со схемами аргументов, проверкой и единым форматом ошибок:
  `search_transactions`, `spending_summary`, `find_recurring_payments`.
- **Цикл агента**: вопрос → модель выбирает инструмент → код проверяет аргументы и выполняет
  функцию → результат передаётся модели → ответ пользователю. Число шагов ограничено.
- **Смена провайдера через `.env`**: GigaChat или любой OpenAI-совместимый API
  (Z.ai GLM, Groq, OpenRouter, Ollama) — без правок кода.
- **Журнал шагов**: в терминале видно, какой инструмент вызван, с какими аргументами и что вернул.

## Установка

Нужен Python 3.10 или новее. Команды выполняются из корня репозитория.

macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Windows (PowerShell):

```powershell
python.exe -m venv .venv
.\.venv\Scripts\Activate.ps1
python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` впишите `GIGACHAT_CREDENTIALS` — Authorization Key из кабинета GigaChat
(developers.sber.ru → GigaChat API), без префикса `Basic` или `Bearer`.
Готовый `.env` сохраняйте при обновлении проекта: он не попадает в Git.

## Запуск

```bash
python run_chat.py --statement data/sample_statement.csv
```

Другие варианты:

```bash
python run_chat.py                                    # выписку загрузить потом командой /load
python run_chat.py --statement data/sample_statement.csv --message "Какие у меня подписки?"
python run_chat.py --env-file .env.glm                # другой файл настроек, например другой провайдер
python run_chat.py --quiet                            # без журнала шагов агента
```

Команды чата:

| Команда | Действие |
|---|---|
| `/load <путь>` | загрузить CSV-выписку (история диалога очищается) |
| `/statement` | какая выписка загружена: период, число операций, валюты |
| `/reset` | очистить историю диалога |
| `/help` | справка |
| `/exit` или Ctrl+C | выход |

Пример сессии:

```text
Вы: скок я потратил на кафешки в октябре??
  [✓ spending_summary] {"date_from": "2026-10-01", "date_to": "2026-10-31", "category": "кафе и рестораны"} → итого 7301.43 RUB

Агент: В октябре на кафе и рестораны ушло 7 301,43 ₽ — 8 операций.
```

### Примеры вопросов

- Сколько я потратил в сентябре и на что больше всего?
- Покажи 5 самых крупных покупок за октябрь.
- Какие у меня подписки и сколько они стоят в месяц?
- Как менялись расходы по месяцам?
- Что было с Ozon 14 октября? Кажется, списали дважды.
- Сколько я потратил в евро?
- Переведи 5000 маме — агент откажет: он только читает и считает.

## Выписка

CSV в UTF-8, разделитель `,` или `;`, первая строка — заголовок:

```csv
operation_id,date,description,amount,currency,mcc
OP-00001,2026-08-01,Перекрёсток,-1726.31,RUB,5411
OP-00042,2026-08-20,Зарплата,65000.00,RUB,6012
```

- `amount` — со знаком: расход отрицательный, поступление положительное.
- `currency` — `RUB`, `USD`, `EUR` или `CNY`. Разные валюты никогда не складываются.
- `mcc` — код категории продавца; по нему код определяет категорию (`src/importers/mcc.py`).

Пример — `data/sample_statement.csv`: 207 вымышленных операций за август–октябрь 2026,
есть подписки, зарплата, траты в USD и EUR и двойное списание. Пересоздать файл:
`python scripts/generate_statement.py` (генерация детерминирована).

## Инструменты

Модель видит только имя, описание и JSON-схему аргументов. Аргументы проверяются кодом
(pydantic) до выполнения. Все инструменты только читают и считают и ничего не меняют.

| Инструмент | Тип | Что делает | Главные ограничения |
|---|---|---|---|
| `search_transactions` | чтение | операции по периоду, категории, тексту, направлению, сумме; сортировка | `limit` 1–50, `text` ≤ 50 символов |
| `spending_summary` | вычисление | сумма расходов или поступлений по категориям, месяцам или продавцам, доли в % | `top_n` 1–30, отдельно по валютам |
| `find_recurring_payments` | вычисление | подписки и регулярные платежи, стоимость в месяц, следующая дата списания | 2–12 повторений, отклонение суммы 0–50 % |

Общие проверки: даты в формате `ГГГГ-ММ-ДД` и реально существующие, `date_from ≤ date_to`,
категория из списка, неизвестные аргументы запрещены.

Ответ инструмента всегда в одном формате:

```json
{"ok": true, "tool": "spending_summary", "result": {"by_currency": [...]}}
{"ok": false, "tool": "search_transactions", "error": {"code": "invalid_arguments",
  "message": "Аргументы не прошли проверку.", "details": ["limit: должно быть не больше 50"]}}
```

Коды ошибок: `invalid_arguments`, `unknown_tool`, `no_statement`, `tool_failed`.
Ошибка уходит модели как данные, и модель может исправить аргументы на следующем шаге.
Пустой результат — не ошибка: `ok: true`, `total_found: 0` и пояснение в `note`.

## Настройки

Формат `.env`: `ИМЯ=значение`. Настройки читаются при запуске, после изменений нужен перезапуск.
Переменные окружения процесса имеют приоритет. Файл `.env` нужен и при их использовании.
Значения в таблице соответствуют `.env.example`. Диапазоны проверяются в `src/config.py`.

| Параметр | Значение в шаблоне | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `gigachat` | Провайдер модели: `gigachat` или `openai` (OpenAI-совместимый API). |
| `GIGACHAT_CREDENTIALS` | Пусто, заполняется локально | Authorization Key. Обязателен для `gigachat`; временный access token получает SDK. |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` | Тип доступа, соответствующий ключу. Значение для физлиц; есть также `GIGACHAT_API_B2B` и `GIGACHAT_API_CORP`. |
| `GIGACHAT_MODEL` | `GigaChat-2-Pro` | Идентификатор модели GigaChat. Без значения — `GigaChat-2`. |
| `GIGACHAT_BASE_URL` | `https://api.giga.chat/v1/` | Адрес API модели. |
| `GIGACHAT_AUTH_URL` | `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` | Адрес получения access token. |
| `GIGACHAT_CA_BUNDLE_FILE` | Пусто | Путь к дополнительному PEM-сертификату относительно `.env`. Используется обоими провайдерами. |
| `GIGACHAT_TIMEOUT` | `30` | Сетевой тайм-аут в секундах, от 1 до 120. Общий для обоих провайдеров. |
| `GIGACHAT_MAX_TOKENS` | `1024` | Максимум токенов в одном ответе, от 1 до 4096. Общий для обоих провайдеров. |
| `GIGACHAT_TEMPERATURE` | `0.3` | Вариативность генерации, от 0 до 2. Общая для обоих провайдеров. |
| `APP_MAX_HISTORY_TURNS` | `5` | Число последних пар вопрос–ответ в истории, от 1 до 50. |
| `APP_MAX_INPUT_CHARS` | `4000` | Максимум символов в одном сообщении пользователя, от 1 до 16000. |
| `APP_MAX_AGENT_STEPS` | `5` | Максимум обращений к модели на один вопрос, от 1 до 10. |
| `OPENAI_BASE_URL` | Пусто | Адрес OpenAI-совместимого API. HTTPS; HTTP — только для `localhost`. |
| `OPENAI_API_KEY` | Пусто | Ключ OpenAI-совместимого API (для Ollama не нужен). |
| `OPENAI_MODEL` | Пусто | Модель OpenAI-совместимого API. |

Если необязательный параметр пуст или отсутствует, берётся значение из кода.
`APP_MAX_HISTORY_TURNS=5` хранит до 5 прошлых пар вопрос–ответ. Промежуточные вызовы
инструментов в историю не попадают, только вопрос и итоговый ответ.

### Смена провайдера

Провайдер меняется только в `.env`. Удобно держать отдельный файл и выбирать его флагом `--env-file`:

```dotenv
# .env.glm — Z.ai GLM (бесплатная модель glm-4.5-flash)
LLM_PROVIDER=openai
OPENAI_BASE_URL=https://api.z.ai/api/paas/v4/
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=glm-4.5-flash
```

```dotenv
# .env.ollama — локальная модель без ключа: ollama run qwen3:8b
LLM_PROVIDER=openai
OPENAI_BASE_URL=http://localhost:11434/v1
OPENAI_MODEL=qwen3:8b
```

### Модели GigaChat

| `GIGACHAT_MODEL` | Особенность |
|---|---|
| `GigaChat-2` | Lite: быстрые ответы и меньшая стоимость. Хорошо вызывает инструменты, но может путать в ответе суммы по продавцам и отдельные операции. |
| `GigaChat-2-Pro` | Рекомендуемая модель проекта: точнее выбирает инструменты и пересказывает результаты. |
| `GigaChat-2-Max` | Сложные задачи с повышенными требованиями к качеству ответа. |
| `GigaChat-3-Ultra` | Модель третьего поколения, доступна физлицам в freemium-режиме. |

Доступность зависит от подключения и квоты. Актуальные варианты —
в [документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/selecting-a-model).

### Сертификат

Если при запуске появляется «Не удалось подключиться к GigaChat… сертификаты» (обычно на macOS),
Python не доверяет корневому сертификату Минцифры. Проверку HTTPS не отключаем, а добавляем сертификат:

```bash
mkdir -p certs
curl -fsSL -o certs/russian_trusted_root_ca.pem https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
```

```dotenv
GIGACHAT_CA_BUNDLE_FILE=certs/russian_trusted_root_ca.pem
```

Файл должен существовать по указанному пути. Он публичный и используется для проверки HTTPS.
`.env`, `.env.*` (кроме `.env.example`), `certs/`, `.venv/` и `data/local/` исключены из Git.

## Код

```text
run_chat.py                  запуск
src/
    cli.py                   терминал: команды, /load, журнал шагов
    chat.py                  диалог и цикл агента с лимитом шагов
    config.py                чтение и проверка настроек, выбор провайдера
    prompts.py               системный промпт
    importers/
        csv_statement.py     чтение и проверка CSV-выписки
        mcc.py               категории по MCC
    tools/
        base.py              контракт инструмента, проверка аргументов, формат ошибок
        statement_tools.py   три инструмента по выписке
    providers/
        __init__.py          выбор провайдера по LLM_PROVIDER
        gigachat.py          GigaChat SDK: сообщения, функции, разбор ответа
        openai_compatible.py OpenAI-совместимый API
        common.py            SSL и тексты ошибок API
data/sample_statement.csv    синтетическая выписка
scripts/generate_statement.py генерация синтетической выписки
docs/SPECIFICATION.md        спецификация агента
tests/                       автоматические проверки
```

Обработка вопроса: `cli.py` → `ChatSession.ask()` → `model.complete(messages, tools)` →
`ToolRegistry.execute()` → снова `model.complete()` → ответ.
Договорённости по коду и зависимостям — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Проверка

```bash
python -m pytest tests -q
```

Тесты не обращаются к реальному API: модель подменяется сценарием или заглушкой SDK.
Что проверяется:

- **правильный расчёт**: суммы по категориям, месяцам и валютам на выписке с известными ответами;
- **неверные аргументы**: несуществующая дата, категория не из списка, `limit > 50`, лишний аргумент,
  битый JSON — ошибка возвращается модели, и она может исправиться;
- **пустой результат**: нет операций или период вне выписки — успешный ответ с пояснением;
- **ошибка инструмента**: внутренний сбой не роняет агента, подробности не уходят модели;
- **лимит шагов**: зацикленная модель останавливается ровно после `APP_MAX_AGENT_STEPS` обращений;
- загрузка CSV с ошибками, формат запросов к GigaChat и OpenAI-совместимому API, выбор провайдера.
