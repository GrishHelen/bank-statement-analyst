# Аналитик банковских выписок

Учебный проект для анализа расходов, регулярных платежей, подписок и аномалий.
Сейчас реализован консольный чат с GigaChat: история диалога, команды и обработка
ошибок API.

Для разработки и проверки используем только синтетические выписки.

## Запуск

```powershell
python.exe -m pip install -r requirements.txt
```

Для первого запуска нужен локальный `.env` на основе `.env.example`.
В `GIGACHAT_CREDENTIALS` указать Authorization Key из кабинета GigaChat,
без префикса `Basic` или `Bearer`. Готовый `.env` при обновлении проекта сохранить.

```powershell
python.exe run_chat.py
```

Дополнительные аргументы: `--env-file .env.local` — другой файл настроек,
`--message "Привет"` — один запрос к модели с завершением программы.

Команды чата: `/help`, `/reset`, `/exit`. Ctrl+C тоже завершает работу.
История хранится в памяти и очищается при выходе. В неё попадают только завершённые
пары вопрос–ответ. $\color{red}{\text{После ошибки можно повторить сообщение; автоматических повторов нет.}}  $

## Настройки

Формат `.env`: `ИМЯ=значение`.
Настройки читаются при запуске, поэтому после изменений нужен перезапуск.
Переменные окружения процесса имеют приоритет. Файл `.env` нужен и при их использовании.

Значения в таблице соответствуют `.env.example`. Диапазоны проверяются в `src/config.py`.

| Параметр | Значение в шаблоне | Назначение |
|---|---|---|
| `GIGACHAT_CREDENTIALS` | Пусто, заполняется локально | Authorization Key. Обязателен; временный access token получает SDK. |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` | Тип доступа, соответствующий ключу. Это значение — для физлиц; бизнес-варианты указаны ниже. |
| `GIGACHAT_MODEL` | `GigaChat-2` | Идентификатор модели. |
| `GIGACHAT_BASE_URL` | `https://api.giga.chat/v1/` | Адрес API модели. |
| `GIGACHAT_AUTH_URL` | `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` | Адрес получения access token. |
| `GIGACHAT_CA_BUNDLE_FILE` | Пусто | Путь к дополнительному PEM-сертификату относительно `.env`. |
| `GIGACHAT_TIMEOUT` | `10` | Сетевой тайм-аут в секундах, от 1 до 120. |
| `GIGACHAT_MAX_TOKENS` | `1024` | Максимум токенов в одном ответе, целое от 1 до 4096. |
| `GIGACHAT_TEMPERATURE` | `0.3` | Вариативность генерации, от 0 до 2. Меньше — обычно более предсказуемые формулировки. |
| `APP_MAX_HISTORY_TURNS` | `5` | Число последних пар вопрос–ответ для истории, целое от 1 до 50. |
| `APP_MAX_INPUT_CHARS` | `4000` | Максимум символов в одном сообщении пользователя, целое от 1 до 16000. |

Если необязательный параметр пуст или отсутствует, берётся значение из кода.

`GIGACHAT_MAX_TOKENS` ограничивает длину ответа в токенах.
`APP_MAX_HISTORY_TURNS=5` сохраняет до 5 прошлых пар вопрос–ответ (10 прошлых сообщений); к ним добавляются системная
инструкция и текущий вопрос. Тайм-аут относится к сетевым операциям, а не ко всему диалогу.

### Модель

| `GIGACHAT_MODEL` | Особенность |
|---|---|
| `GigaChat-2` | Lite: быстрые ответы и меньшая стоимость. Базовая модель проекта. |
| `GigaChat-2-Pro` | Сложные инструкции, анализ и обобщение текста. |
| `GigaChat-2-Max` | Сложные задачи с повышенными требованиями к качеству ответа. |
| `GigaChat-3-Ultra` | Модель третьего поколения, доступна физлицам в freemium-режиме. |

Пример переключения: `GIGACHAT_MODEL=GigaChat-2-Pro`, затем перезапуск чата.
Доступность зависит от подключения и квоты. Актуальные варианты —
в [документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/selecting-a-model).

### Сертификат

Если Python не доверяет сертификату GigaChat, подключаем корневой сертификат:

```dotenv
GIGACHAT_CA_BUNDLE_FILE=certs/russian_trusted_root_ca.pem
```

Файл должен существовать по указанному пути. Он публичный и используется для проверки
HTTPS. 
`.env`, `certs/`, `.venv/` и локальные данные исключены из Git.
В репозитории хрнv.example` без ключа.

## Код

```text
run_chat.py              запуск
src/
    __main__.py          запуск через python -m src
    cli.py               ввод, вывод и команды
    chat.py              история диалога и обращение к модели
    config.py            чтение и проверка настроек
    prompts.py           системный промпт
    providers/
        gigachat.py      клиент GigaChat и разбор ответов
tests/                   тесты чата, настроек и API-адаптера
```

Обработка сообщения: `cli.py` → `ChatSession.ask()` → `GigaChatModel.complete()`.
После успешного ответа сохраняется новая пара сообщений и сокращается история.
Работа с SDK сосредоточена в `providers/`; сейчас реализован только GigaChat.
Договорённости по коду и зависимостям — в [CONTRIBUTING.md](CONTRIBUTING.md).
