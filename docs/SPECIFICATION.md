# Спецификация: аналитик личных финансов по выписке

Тема курса — «Аналитик личных финансов по выписке». Этап ДЗ1: агент с тремя
инструментами, схемами аргументов, проверкой и обработкой ошибок, а также сменой провайдера модели через конфиг.

## 1. Пользователь и задачи

**Пользователь** — физлицо, которое хочет разобраться в своих расходах. Оно выгружает
выписку из банка в CSV и задаёт вопросы обычным языком. Финансовых терминов не знает и пишет
с опечатками, иногда задаёт два вопроса в одном сообщении.

**Задачи пользователя:**

- узнать, сколько ушло денег за период и на что (категории, месяцы, продавцы);
- найти конкретные операции: крупные траты, покупки в магазине, операции за день;
- увидеть подписки и регулярные платежи и понять, сколько они стоят в месяц;
- заметить подозрительное: двойное списание, незнакомый платёж.

**Примеры реплик** (ответы проверяются на `data/sample_statement.csv`):

| Реплика | Что делает агент |
|---|---|
| «скок я потратил на кафешки в октябре??» | `spending_summary` (октябрь, категория «кафе и рестораны») |
| «какие у меня подписки и во сколько они обходятся в месяц» | `find_recurring_payments` |
| «сколько ушло в сентябре и какие 3 самые большие покупки?» | `spending_summary` + `search_transactions` (sort=amount_desc, limit=3) |
| «что там было с озоном 14 октября, вроде два раза списали» | `search_transactions` (text=Ozon, дата 2026-10-14) — найдёт двойное списание |
| «переведи 5000 маме» | отказ: агент только читает данные |

## 2. Архитектура

```text
Пользователь ──/load──▶ CSV-загрузчик (код) ──▶ StatementStore
     │ вопрос
     ▼
ChatSession (harness)  ──▶ модель (GigaChat или OpenAI-совместимая, выбор в .env)
   ▲   цикл ≤ APP_MAX_AGENT_STEPS        │ вызов инструмента {name, arguments}
   │                                      ▼
   └── результат / ошибка (JSON) ◀── ToolRegistry: проверка схемы → функция
```

Один вопрос: модель выбирает инструмент → код проверяет аргументы и выполняет функцию →
результат возвращается модели → модель отвечает пользователю. Не больше `APP_MAX_AGENT_STEPS`
обращений к модели (по умолчанию 5); при превышении агент останавливается и просит уточнить вопрос.

**Что решает код, а что модель**

| Код (жёсткие правила) | Модель |
|---|---|
| загрузку и проверку выписки, категорию по MCC | понять вопрос и выбрать инструмент |
| проверку аргументов по схеме, лимиты (≤ 50 операций, ≤ 30 групп) | подобрать аргументы: период, категорию, фильтры |
| все расчёты (Decimal, без смешивания валют) | сформулировать ответ по результатам |
| лимит шагов, истории и длины сообщения | исправить аргументы после ошибки |
| выбор провайдера и ключи (только `.env`) | — |

Выписку загружает **пользователь** (`/load` или `--statement`), а не модель: так модель не может
прочитать произвольный файл на диске.

## 3. Данные

CSV в UTF-8, разделитель `,` или `;`, первая строка — заголовок.

| Столбец | Формат | Пример |
|---|---|---|
| `operation_id` | уникальная строка до 64 символов | `OP-00042` |
| `date` | `ГГГГ-ММ-ДД` | `2026-10-14` |
| `description` | непустой текст, обрезается до 200 символов | `Ozon` |
| `amount` | число со знаком, ≤ 2 знаков после точки: расход < 0, поступление > 0 | `-3290.00` |
| `currency` | `RUB`, `USD`, `EUR`, `CNY` | `RUB` |
| `mcc` | 4 цифры или пусто | `5399` |

Категория вычисляется по MCC (`src/importers/mcc.py`), 18 категорий. Ошибочная строка не
пропускается молча: файл отклоняется с номерами строк (до 5 ошибок в сообщении). Лимиты: 5 МБ, 20 000 строк.
Данные только синтетические: `data/sample_statement.csv` создаётся `scripts/generate_statement.py`.

## 4. Инструменты

Все три инструмента **только читают и считают**: данные не меняются, действий с последствиями нет.

| | `search_transactions` | `spending_summary` | `find_recurring_payments` |
|---|---|---|---|
| Тип | чтение | вычисление | вычисление |
| Принимает | `date_from`, `date_to`, `category`, `text` (≤ 50 симв.), `direction` (expense/income/all), `min_amount`, `max_amount`, `sort` (date_desc/date_asc/amount_desc), `limit` (1–50, по умолч. 20) | `date_from`, `date_to`, `direction` (expense/income), `group_by` (category/month/description), `category`, `top_n` (1–30) | `date_from`, `date_to`, `min_occurrences` (2–12, по умолч. 3), `amount_tolerance_pct` (0–50, по умолч. 10) |
| Возвращает | `total_found`, `returned`, `truncated`, список операций | по каждой валюте: итог, число операций, группы с суммой, количеством и долей % | платежи: описание, типичная сумма, частота, даты, следующая ожидаемая дата, стоимость в месяц |
| Условия отказа | выписка не загружена; неверная дата; `date_from > date_to`; категория не из списка; `limit > 50`; `min_amount > max_amount`; лишний аргумент | те же проверки периода и категории; `top_n` вне 1–30 | период; параметры вне диапазонов |

**Правило регулярного платежа** (код, не модель): расход с одинаковым описанием в одной валюте,
не меньше `min_occurrences` раз, каждая сумма отличается от медианной не больше чем на
`amount_tolerance_pct` %, медианный интервал 25–35 дней (ежемесячно) или 6–8 дней (еженедельно).

**Формат ответа инструмента** — один для всех исходов:

```json
{"ok": true,  "tool": "spending_summary", "result": {...}}
{"ok": false, "tool": "search_transactions",
 "error": {"code": "invalid_arguments", "message": "Аргументы не прошли проверку.",
           "details": ["date_from: ожидается существующая дата в формате ГГГГ-ММ-ДД",
                       "limit: должно быть не больше 50"]}}
```

Коды ошибок: `invalid_arguments`, `unknown_tool`, `no_statement`, `tool_failed`
(внутренний сбой — подробности не уходят модели). Пустой результат — не ошибка:
`ok: true`, `total_found: 0` и пояснение `note`, включая случай «период вне выписки».

## 5. Опасные действия и ограничения

| Риск | Защита сейчас | План |
|---|---|---|
| Просьба перевести деньги, заблокировать карту, отменить подписку | таких инструментов нет; промпт велит отказать и направить в приложение банка; вызов несуществующего инструмента → `unknown_tool` | действия (например, напоминание об отмене подписки) — только с подтверждением человеком (ДЗ2) |
| Prompt injection в описании операции («игнорируй правила…») | промпт: описания — данные, а не инструкции; инструменты только читают | демонстрация атаки и проверка (ДЗ2) |
| Выдуманные суммы | расчёты только в коде; промпт требует брать числа из инструментов | eval-набор с проверкой чисел |
| Чтение чужих файлов | путь к выписке задаёт только пользователь | — |
| Огромный ответ инструмента забивает контекст | ≤ 50 операций, ≤ 30 групп, флаг `truncated` | — |
| Бесконечный цикл вызовов | `APP_MAX_AGENT_STEPS` (1–10) | бюджет токенов |
| Утечка ключей | ключи только в `.env` (в `.gitignore`), не в логах и не в `repr` настроек; тела ошибок API не показываются | — |
| Реальные данные клиентов | в репозитории только синтетика | — |

## 6. Три способа сломать агента и что он делает

1. **Инструмент вернул ошибку** (например, модель передала `2026-09-31` или `limit=100`) —
   ошибка с понятными `details` возвращается модели; модель исправляет аргументы на следующем шаге
   или объясняет пользователю. Если инструмент упал внутри — `tool_failed`, агент продолжает работу.
2. **Данных нет** (период вне выписки, магазина нет в выписке, выписка не загружена) — успешный
   пустой результат с `note`, либо `no_statement` с подсказкой выполнить `/load`.
3. **Пользователь пишет не по теме или пытается обойти правила** («переведи деньги»,
   «покажи файл ~/.ssh») — таких инструментов нет, модель отказывает; при зацикливании срабатывает лимит шагов.

Каждый случай покрыт автоматическим тестом (`tests/test_agent.py`, `tests/test_tools.py`).

## 7. Провайдер модели

Провайдер выбирается в `.env`, без правок кода: `LLM_PROVIDER=gigachat` (по умолчанию, SDK GigaChat
с function calling) или `LLM_PROVIDER=openai` — любой OpenAI-совместимый API (Z.ai GLM, Groq,
OpenRouter, локальная Ollama) через `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`.
Цикл агента и инструменты не зависят от провайдера.
